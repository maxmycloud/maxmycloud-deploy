Standard Edition

Step-by-step installation process

Introduction

This guide walks through installing the Standard Edition of MaxMyCloud — our multi-tenant SaaS offering. Standard Edition customers all sign in at app.maxmycloud.com. Follow the steps in order for a smooth setup.

Target audience: System Administrators, IT Professionals.

Prerequisites

  • An active MaxMyCloud subscription.
  • A Snowflake account with privileges to install applications and create roles — ACCOUNTADMIN recommended.
  • A modern web browser.
  • An authenticator app on your phone (Google Authenticator, Microsoft Authenticator, Authy, 1Password, etc.) — needed to complete MFA enrollment at first sign-in.
  • OpenSSL on your workstation (for generating the Snowflake key pair in Section 1.4). Pre-installed on macOS and Linux; on Windows use WSL or Git-Bash.

1. Snowflake Setup

Complete all of Section 1 once per Snowflake account you want MaxMyCloud to monitor. If you have separate prod / dev / business-unit accounts, repeat the section for each. Each account gets its own Native App install, its own role, and its own service user + key pair.

1.1 · Share your Snowflake account identifier(s) and first admin email

MaxMyCloud distributes the Monitor Center Native App through Snowflake Private Listing, and creates your first user account in the MaxMyCloud SaaS. We need two things from you to get started:

  1. Your Snowflake account identifier(s) — so we can publish the Native App private listing to each account.
  2. The email address of your first admin user — the person who will sign in first to your MaxMyCloud tenant.

For each Snowflake account you want to monitor, run this in a Snowflake worksheet to get the identifier:

SELECT CURRENT_ORGANIZATION_NAME() || '.' || CURRENT_ACCOUNT_NAME();

Alternatively, in the Snowsight UI: click your user profile at the bottom → Account → View account details → Copy data sharing account identifier.

Send both items — the account identifier(s) and the first admin's email — to your MaxMyCloud contact (or support@maxmycloud.com). Sending them together lets MaxMyCloud publish the private listing and provision your user account in parallel; both are typically ready the same business day.

You'll receive an email confirmation from MaxMyCloud once the Native App private listing is live in each Snowflake account.

Wait for confirmation from MaxMyCloud before starting Section 1.2 — the Native App won't appear in your Snowsight UI until the private listing has been published to your account.

1.2 · Install the Native App

In Snowsight, sign in as an admin who can install applications, then:

  1. Navigate to Data Products → Apps in the left navigation.
  2. Under Recently Shared with You, find Monitor Center (MaxMyCloud) and click Get to download.
  3. Once the download completes, the app appears under Installed Apps. Click Monitor Center to begin installation.
  4. Select SNOWFLAKE_INSIGHT. Snowflake starts the installation.
  5. Two authorization prompts appear requesting Snowflake privileges — click Grant Privileges, then Allow, on each. The requested account-level privileges include IMPORTED PRIVILEGES ON DATABASE SNOWFLAKE, MANAGE WAREHOUSES, EXECUTE TASK, and EXECUTE MANAGED TASK.

Installation usually completes in under 30 seconds. A green checkmark on the Monitor Center welcome screen confirms the install; the initial data refresh starts automatically in the background and it's safe to close the app window.

1.3 · Create the MaxMyCloud role

MaxMyCloud uses a dedicated Snowflake role — maxmycloud_role — to query the Native App and the warehouse metadata it needs. Run this as ACCOUNTADMIN in a Snowflake worksheet:

CREATE ROLE maxmycloud_role;

GRANT APPLICATION ROLE monitor_center.app_maxmycloud   TO ROLE maxmycloud_role;
GRANT USAGE ON WAREHOUSE your_warehouse                TO ROLE maxmycloud_role;
GRANT USAGE ON INTEGRATION MAXMYCLOUD_API_INTEGRATION  TO ROLE maxmycloud_role;
GRANT IMPORTED PRIVILEGES ON DATABASE SNOWFLAKE        TO ROLE maxmycloud_role;

Replace your_warehouse with the warehouse you want MaxMyCloud to use for its own queries. An X-Small warehouse is typically sufficient. Note the warehouse name — you'll enter it in Section 3.

1.4 · Create the Snowflake service user (key-pair authentication)

MaxMyCloud's backend processes — scheduled health checks, ongoing warehouse monitoring, autosize actions, subscription refresh — authenticate to your Snowflake account as a dedicated maxmycloud service user, using a key pair. Key-pair auth is the standard Snowflake pattern for machine-to-machine access: the key never appears in a login prompt, never expires on a schedule, and never rotates through the user-password channel. No human logs in with this credential.

a. Generate a key pair on your workstation

openssl genrsa 2048 | openssl pkcs8 -topk8 -inform PEM -out rsa_key.p8 -nocrypt
openssl rsa -in rsa_key.p8 -pubout -out rsa_key.pub

You'll get two files:

  • rsa_key.p8 — the private key. Keep this safe; you'll paste its contents into the MaxMyCloud UI in Section 3.
  • rsa_key.pub — the public key. Its content goes into the Snowflake user in the next step.

b. Create the Snowflake user

Run as ACCOUNTADMIN:

CREATE OR REPLACE USER maxmycloud
  PASSWORD          = ''              -- empty for key-pair auth
  LOGIN_NAME        = 'maxmycloud'
  DISPLAY_NAME      = 'maxmycloud'
  DEFAULT_WAREHOUSE = 'your_warehouse'
  DEFAULT_ROLE      = 'maxmycloud_role'
  DISABLED          = FALSE;

GRANT ROLE maxmycloud_role TO USER maxmycloud;

c. Attach the public key to the Snowflake user

Open rsa_key.pub in a text editor. Copy the content between the -----BEGIN PUBLIC KEY----- and -----END PUBLIC KEY----- lines — a single block with no line breaks — and run:

ALTER USER maxmycloud SET RSA_PUBLIC_KEY='MIIBIjANBgkqh…';

Verify the key attached correctly:

DESC USER maxmycloud;

Confirm RSA_PUBLIC_KEY_FP in the output is non-empty.

Gather these details before moving on to Section 3 — you'll enter them yourself in the MaxMyCloud UI to wire up the connection:
  • Snowflake account identifier (from Section 1.1)
  • Warehouse name (from Section 1.3)
  • Service username — maxmycloud
  • Service role — maxmycloud_role
  • Private key file contents — rsa_key.p8

2. MaxMyCloud Provisions Your First User

Once your Native App install is confirmed (Section 1.2 complete), let your MaxMyCloud contact know. MaxMyCloud will then provision your first admin user account inside your MaxMyCloud tenant, using the email address you provided in Section 1.1.

Here's what happens next, from your side:

  1. The first admin receives an automatic email from MaxMyCloud with a set-your-password link. Link is valid for 24 hours — ask us to resend if it expires.
  2. Click the link, set a password.
  3. Because admin accounts require two-factor authentication, you'll be prompted to enroll in MFA using an authenticator app (Google Authenticator, Microsoft Authenticator, Authy, 1Password, etc.). Scan the QR code and enter a six-digit code to confirm enrollment.
  4. Sign in at app.maxmycloud.com using your email address, password, and the six-digit code from your authenticator app.

You're now signed in as the tenant admin. Continue to Section 3 to connect your Snowflake account.

3. Add Your Snowflake Account in MaxMyCloud

Now that you're signed in, wire your Snowflake account into MaxMyCloud yourself — using the details you gathered at the end of Section 1.

  1. In the MaxMyCloud UI, navigate to Settings → Accounts.
  2. Click Add Account.
  3. Fill in the form using the mapping below.
  4. Click Add Account at the bottom. MaxMyCloud tests the connection and starts the initial data refresh.
Form field What to enter
Account Name A friendly display name, e.g. Prod, Dev, or your Snowflake account name. Shown in the account picker.
Account Identifier The identifier from Section 1.1 — e.g. MYORG-MYACCOUNT.
Warehouse The warehouse you granted in Section 1.3.
Authentication Mode Select Key Pair. (Snowflake SSO is greyed out on Standard Edition — it's an Enterprise-tier feature.)
Username maxmycloud (the service user from Section 1.4b).
User Role maxmycloud_role (from Section 1.3).
Private Key Paste the full contents of rsa_key.p8, including the -----BEGIN PRIVATE KEY----- and -----END PRIVATE KEY----- header/footer lines.

Once the account saves, MaxMyCloud starts collecting query, warehouse, and cost telemetry from your Native App. The first Health Check is typically ready within a few hours; ongoing warehouse monitoring runs continuously.

If you set up multiple Snowflake accounts in Section 1, repeat this Section 3 for each additional account.

4. Ongoing Operations

Everything below is self-service — no MaxMyCloud involvement required.

4.1 · Adding more Snowflake accounts yourself

  1. Send the new account identifier to MaxMyCloud (via support@maxmycloud.com) so we can publish the Native App private listing to it. No new user email needed — your existing MaxMyCloud tenant covers all accounts.
  2. Complete Sections 1.2 – 1.4 for the new Snowflake account — Native App install, role, service user + key pair.
  3. Follow Section 3 to add the new account in the MaxMyCloud UI.

4.2 · Inviting more MaxMyCloud users

Navigate to Settings → Users → Add User in the MaxMyCloud UI.

Enter the invitee's email address and select their role (User or Admin). MaxMyCloud sends them a set-your-password link by email. Once they set their password, they can sign in with email + password. Admin users are prompted to enroll in authenticator-app MFA on first sign-in, same as your original admin.

You can revoke a user at any time from the same Users page.
